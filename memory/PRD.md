# PRD — Developmental Writing Studio (Milestone 1)

## Original Problem Statement
Build Milestone 1 ONLY of an AI writing app that develops students as writers through scaffolded conversation (never editing, grading, or writing for them). Validate the loop: Teacher defines purpose → Student submits writing → AI evaluates organization relative to purpose → AI gives ONE focused developmental invitation → student responds/revises → AI updates internal developmental theory → AI generates next invitation.

## Architecture
- **Backend** (FastAPI + MongoDB): `/api/sessions` (create), `/api/sessions/{id}` (get), `/api/sessions/{id}/interact` (run engine). Developmental engine uses Claude **claude-sonnet-4-6** via emergentintegrations (EMERGENT_LLM_KEY), returns structured JSON: one student-facing invitation + a fully updated internal `DevelopmentalState`. State is UPDATED (merged), not appended, each turn. Sessions + turns + dev_state persisted in `sessions` collection.
- **Frontend** (React): 3 screens on a single continuous page. `App.js` state machine (setup → workspace) with localStorage session persistence (`dws_session_id`). Academic/editorial theme (Cormorant Garamond + IBM Plex Sans/Mono, cream/ink/terracotta).

## Screens Implemented (2026-07-17)
1. **Teacher Setup** — Assignment, Pedagogical Purpose, Current Writing Task, Optional Teacher Notes, Begin Session.
2. **Student Workspace** — assignment/task header, large writing canvas + Continue/Send revised draft, continuous conversation thread with answer/explain reply modes. No page transitions.
3. **Hidden Development Panel** — collapsible dark "terminal" drawer showing purpose, developmental theory, primary tension, alternative interpretations, selected scaffold + rationale, candidate scaffolds, developmental movement, uncertainties.

## Verified
- Multi-turn loop works: dev_state visibly evolves (developmental_movement ≠ initial), invitations are single-focus, never rewrite student work, never list errors. Persistence across reload confirmed. Testing agent: backend 6/6, frontend critical flows 100%.

## Milestone 5A — Writing Instruction Boundary & Anti-Coauthoring (2026-06)
- Established a strict boundary: the AI develops better WRITERS, not better essays. It teaches HOW writing works (purpose, organization, thesis/paragraph FUNCTION, reader orientation, transitions, clarity, coherence, rhetorical function, interpreting the student's OWN evidence) and must NEVER supply substantive CONTENT (additional arguments, reasons, examples, evidence, stronger/new claims, stakes, emotional appeals, policy suggestions). Enforced purely in the reasoner system prompt — NO engine/instruction-layer/UI/domain changes.
- Added WRITING INSTRUCTION BOUNDARY + ANTI-COAUTHORING rule + per-turn SELF-CHECK to `server.py` prompt (after STUDENT-FACING INVITATION RULES, ~lines 266-272). Added two intervention output fields: `focus` ('writing'|'content') and `writing_not_content_check` (self-audit). CONTENT MODE is a narrow exception: allowed only when the teacher explicitly enables brainstorming (assignment/purpose/teacher_notes) or the student explicitly requests idea generation.
- Eval: 30 cases across argumentative/narrative/informative/analytical (`tests/milestone5a_boundary_eval.py` → `milestone5a_results.json`; review `test_reports/milestone5a_review.md`) — **30/30 boundary PASS**; 0 content-coaching red-flag phrases; focus='writing' on all 29 instructional cases; focus='content' correctly only on the 1 teacher-enabled brainstorming case (ownership kept with student). Before/after example: three-reason thesis no longer prompted with "what would make it stronger" (content) but with thesis-function questions (writing).
- Testing agent iteration_10: backend M1–M5 regression PASS (7/7 clean second run; 1 first-run SSE-parse flake passed on retry — test-client artifact, not a product bug). No critical issues; anti-coauthoring holds; focus/writing_not_content_check populate correctly; brainstorming exception works. Latency ~30–41s/turn, no 502s.
